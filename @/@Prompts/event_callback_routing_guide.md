# 事件回调路由配置指南

## 1. 标题
OMS事件回调路由配置模块

## 1.1 功能概述
事件回调路由配置模块是OMS系统中的一个重要组件，用于管理和配置系统事件的外部通知机制。该模块允许用户创建、编辑和管理事件回调规则，实现系统事件（如订单创建、发货、库存变更等）的实时通知和数据同步。

## 1.2 用户故事

### 作为系统管理员
1. 我希望能够配置不同类型的事件通知规则，以便将系统事件实时推送给相关方
2. 我需要为不同的商户配置不同的回调规则，以满足他们各自的集成需求
3. 我想要在启用规则之前测试连接的可用性，以确保配置的正确性
4. 我需要能够快速复制现有规则，以便快速创建相似的配置

### 作为商户技术人员
1. 我需要接收特定类型的事件通知，以便实时处理系统变更
2. 我希望能够选择合适的认证方式，以确保数据传输的安全性
3. 我需要在系统升级或变更时能够及时调整回调配置

### 作为运维人员
1. 我需要查看和管理所有的回调规则，以便进行系统维护
2. 我希望能够快速定位和处理回调失败的情况
3. 我需要能够临时禁用某些规则，以进行系统维护或故障处理

## 1.3 业务流程

### 规则创建流程
1. 用户进入事件回调配置页面
2. 点击"添加规则"按钮
3. 填写规则基本信息
   - 规则名称
   - 选择适用商户
   - 选择适用仓库（可选）
   - 选择事件类型
4. 配置返回方式
   - 选择返回类型（Webhook/Email/API/Topic）
   - 填写目标地址
5. 配置认证信息（根据选择的认证方式）
   - Basic Auth
   - Bearer Token
   - HMAC签名
   - Header认证
   - 自定义认证
6. 测试连接
7. 启用规则

### 规则管理流程
1. 查看规则列表
2. 筛选和搜索规则
3. 编辑现有规则
4. 复制规则
5. 启用/禁用规则
6. 删除规则

## 1.4 业务规则

### 规则命名和唯一性
1. 规则名称必须唯一
2. 规则名称长度为3-50个字符
3. 规则名称支持中英文、数字、下划线

### 商户和仓库配置
1. 必须选择至少一个商户
2. 仓库选择为可选项
3. 可以为同一商户配置多个规则

### 事件类型规则
1. 必须选择一个事件类型
2. 事件类型分类：
   - 订单事件（创建、更新、发货）
   - 库存事件（变更、预警）
   - 配送事件（确认）

### 返回类型规则
1. 支持的返回类型：
   - Webhook：需要https URL
   - Email：支持多个邮箱地址（逗号分隔）
   - API：需要https URL
   - Topic：支持层级结构（使用/分隔）
2. 每种返回类型有特定的地址格式验证
3. 返回类型为None时无需配置目标地址

### 认证配置规则
1. 支持多种认证方式：
   - Basic Auth：需要用户名和密码
   - Bearer Token：需要token
   - HMAC签名：需要算法选择和密钥
   - Header认证：支持多个自定义header
   - 自定义认证：支持JSON格式配置
2. 认证信息必须加密存储
3. HMAC签名支持多种算法（SHA256/SHA512/MD5）

### 测试和启用规则
1. 非None返回类型必须进行连接测试
2. 测试失败的规则不能启用
3. 测试成功后才能保存和启用规则
4. 修改配置后需要重新测试

### 重试机制
1. 可配置是否启用重试
2. 重试次数范围：1-10次
3. 每次重试间隔递增

| 字段名 | 类型 | 是否必填 | 描述 | 规则/限制 |

| 事件类型 | Select | 否 | 事件类型下拉选择 | - 分组展示<br>- 单选<br>- 支持清空 |

### 3. 规则配置表单

#### 3.1 基本信息
| 字段名 | 类型 | 是否必填 | 验证规则 | 描述 |
|-------|------|---------|----------|------|
| 规则名称 | Input | 是 | - 长度：3-50字符<br>- 唯一性校验<br>- 支持中英文、数字、下划线 | 规则的唯一标识 |
| 商户 | Select | 是 | - 至少选择1个<br>- 最多选择10个 | 规则适用的商户 |
| 仓库 | Select | 否 | - 可多选<br>- 最多选择10个 | 规则适用的仓库 |
| 事件类型 | Select | 是 | - 单选<br>- 必须选择一个有效值 | 触发事件的类型 |

#### 3.2 返回配置
| 字段名 | 类型 | 是否必填 | 验证规则 | 描述 |
|-------|------|---------|----------|------|
| 返回类型 | Select | 是 | - 单选<br>- 必须选择一个有效值 | 回调的方式 |
| 目标地址 | Input | 条件必填 | - Webhook/API：需要https URL<br>- Email：邮箱格式，多个逗号分隔<br>- Topic：支持/分隔的层级结构 | 回调的目标地址 |

#### 3.3 重试配置
| 字段名 | 类型 | 是否必填 | 验证规则 | 描述 |
|-------|------|---------|----------|------|
| 启用重试 | Switch | - | - 布尔值 | 是否启用重试机制 |
| 重试次数 | InputNumber | 条件必填 | - 范围：1-10<br>- 启用重试时必填 | 最大重试次数 |

#### 3.4 认证配置
| 认证类型 | 配置字段 | 是否必填 | 验证规则 | 描述 |
|---------|----------|---------|----------|------|
| Basic Auth | username<br>password | 是 | - 不能为空<br>- 长度限制：3-50字符 | HTTP基础认证 |
| Bearer Token | token | 是 | - 不能为空<br>- 长度限制：10-200字符 | Bearer令牌认证 |
| HMAC | algorithm<br>secret<br>signatureParam<br>signatureHeader<br>includeBody<br>includeQuery | 是 | - algorithm：必须选择有效值<br>- secret：不能为空<br>- signatureParam：不能为空<br>- signatureHeader：不能为空 | HMAC签名认证 |
| Header | headers | 是 | - 至少一组header<br>- key不能为空<br>- value不能为空 | 自定义Header认证 |
| Custom | custom | 是 | - 必须是有效的JSON格式 | 自定义认证配置 |

##### HMAC算法选项
- SHA256（默认）
- SHA512
- MD5

#### 3.5 其他信息
| 字段名 | 类型 | 是否必填 | 验证规则 | 描述 |
|-------|------|---------|----------|------|
| 状态 | Switch | - | - 布尔值<br>- 测试未通过时禁用 | 规则是否启用 |
| 备注 | Textarea | 否 | - 最大长度：500字符 | 规则的补充说明 |

#### 3.6 测试连接
| 项目 | 说明 | 规则 |
|-----|------|------|
| 触发条件 | - 非None返回类型<br>- 目标地址已填写<br>- 认证信息已配置 | 必须测试通过才能启用和保存 |
| 测试数据 | - eventType：当前选择的事件类型<br>- timestamp：当前时间戳<br>- data：测试消息内容 | 构建模拟数据进行测试 |
| 超时设置 | 10秒 | 超时后显示失败 |
| 重试机制 | 不进行重试 | 仅测试单次连接 |

### 4. 数据格式

#### 4.1 事件数据格式
```json
{
  "eventType": "string",
  "timestamp": "ISO8601",
  "data": {
    "message": "string",
    "testId": "number"
  }
}
```

#### 4.2 认证配置格式
```json
{
  "basic": {
    "username": "string",
    "password": "string"
  },
  "bearer": {
    "token": "string"
  },
  "hmac": {
    "algorithm": "string",
    "secret": "string",
    "signatureParam": "string",
    "signatureHeader": "string",
    "includeBody": "boolean",
    "includeQuery": "boolean"
  },
  "header": {
    "headers": [
      {
        "key": "string",
        "value": "string"
      }
    ]
  },
  "custom": "json_string"
}
```

### 5. 状态码和错误处理

#### 5.1 测试状态码
| 状态码 | 说明 | 处理方式 |
|-------|------|---------|
| 200 | 测试成功 | 允许启用和保存 |
| 401 | 认证失败 | 提示检查认证配置 |
| 404 | 地址不存在 | 提示检查目标地址 |
| 408 | 请求超时 | 提示网络问题 |
| 其他 | 服务器错误 | 显示具体错误信息 |

#### 5.2 验证错误
| 错误类型 | 提示信息 | 处理方式 |
|---------|---------|----------|
| 必填项缺失 | 请填写[字段名] | 红色提示，禁止提交 |
| 格式错误 | 格式不正确，请参考示例 | 显示正确格式示例 |
| 长度超限 | 超出允许的长度范围 | 显示允许的长度范围 |
| 重复名称 | 规则名称已存在 | 提示修改名称 |
