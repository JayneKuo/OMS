# MCP-AI 驱动的订单处理功能需求文档

本功能旨在通过 AI 与 MCP Server 协作，支持用户以自然语言形式完成订单的【查询】与【创建】，实现智能化、自动化的订单处理体验。

---

## 场景 1：查询订单（需求）

### 目标：
用户通过自然语言查询订单状态，包括 OMS 订单号或渠道订单号。系统应能返回订单当前状态，若已发货，则返回对应的发货单号及发货时间；若pending，则返回 命中规则名称。若exception 则返回原因。

### 功能要求：
1. 支持识别并提取用户输入中的订单编号（OMS或渠道订单号）。
2. 查询订单状态并进行语义化的结果返回。
3. 若订单已发货：
   - 返回发货单号。
   - 告知用户发货时间（若可获取）。
4. 若订单为 Pending 状态：
   - 返回 Pending 规则，清晰表达当前阻塞点。
5. 若订单exception
   - 提示用户具体原因。
6.若查询不到订单：
   - 提示用户是否需要创建新订单。

### 示例对话：
- 用户：“查一下订单 SO202506010012 发货了吗？”
- 系统：“订单已发货，物流单号为 SHP123456789。”
- 用户：“渠道订单 30219988 还没发吗？”
- 系统：“订单尚未发货，当前状态为【等待仓库分配】。”

---

## 场景 2：创建订单（需求）

### 目标：
用户通过自然语言请求创建订单，系统应引导用户逐步补全信息，并在校验通过后自动提交订单，创建成功后进行确认反馈；若信息有误或缺失，则及时提示。

### 功能要求：
1. 支持自然语言识别“创建订单”意图。
2. 引导用户提供客户信息（编码或名称）：
   - 若客户不存在，需中止并提示。
3. 查询客户默认仓库信息：
   - 若未配置仓库，提示并终止流程。
4. 引导用户输入商品及数量信息：
   - 支持多 SKU。
   - 校验 SKU 有效性。
5. 引导输入收货地址：
   - 包括街道、城市、州、邮编。
6. 所有信息完整后，执行创建动作。
7. 创建成功后反馈内容包括：
   - 订单编号
   - 收发货信息摘要
8. 若创建失败，返回清晰错误提示原因。

### 示例对话：
- 用户：“帮我下一个订单，2个SKU发往纽约。”
- 系统：“请提供客户编码。”
- 用户：“客户是 CUST001。”
- 系统：“好的，请告诉我商品 SKU 及数量。”
- 用户：“ABC123 × 1，DEF456 × 2。”
- 系统：“收货地址是？”
- 用户：“123 Main St, New York, NY。”
- 系统：“订单创建成功，编号为 SO202506040001，收货地为纽约。”
