# 异常日志模块功能指南 (Exception Logs Module Guide)

## 1. 模块概述

异常日志模块（Exception Logs）是OMS系统中的关键组件，用于记录、跟踪和管理系统运行过程中发生的各种异常情况。本模块主要处理与订单、库存、物流等相关的异常事件，并提供通过邮件通知相关人员的功能。

通过异常日志模块，用户可以：
- 查看所有系统异常记录
- 按多种条件筛选异常记录
- 查看异常详情
- 发送异常通知邮件
- 标记异常为已解决状态

## 2. 界面组件

### 2.1 主界面

异常日志主界面由以下部分组成：
- 页面标题：显示"异常日志 Exception Logs"
- 操作按钮：
  - 刷新按钮：用于刷新数据列表
  - 批量发送按钮：用于批量发送选中或所有未解决异常的邮件通知
- 搜索筛选区域：提供多种筛选条件
- 数据表格：显示异常记录列表，支持多选功能
- 分页控件：用于浏览大量数据

### 2.2 操作按钮

表格中的每条记录有两个主要操作按钮：
- 查看详情（文档图标）：打开详情对话框
- 发送邮件（邮件图标）：仅在邮件状态为"未发送"时显示，用于发送通知邮件

### 2.3 对话框

模块包含四个主要对话框：
- 异常详情对话框：显示异常的详细信息
  - 包含关闭按钮
  - 对于未发送邮件的异常，显示"发送邮件"按钮
  - 对于已发送邮件的异常，显示"重新发送"按钮
- 标记已解决对话框：用于将异常标记为已解决并添加解决方案
- 发送邮件对话框：用于配置和发送单条异常通知邮件
- 批量发送邮件对话框：用于配置和批量发送多条异常通知邮件

## 3. 数据结构

### 3.1 异常记录（LogItem）数据结构

```typescript
interface LogItem {
  id: string;                   // 记录ID
  createTime: string;           // 创建时间
  issueType: string;            // 问题类型
  description: string;          // 问题描述
  channel: string;              // 所属渠道
  channelOrderId: string;       // 渠道订单ID
  systemOrderId: string;        // 系统订单ID
  status: 'unsolved' | 'solved'; // 解决状态
  emailSent: 'sent' | 'unsent' | 'failed'; // 邮件发送状态
  recipients?: string;          // 收件人
  emailContent?: string;        // 邮件内容
  lastSendTime?: string;        // 最后发送/更新时间
  resolveTime?: string;         // 解决时间
  resolveNote?: string;         // 解决方案
  emailHistory?: EmailHistory[]; // 邮件发送历史
}

interface EmailHistory {
  sendTime: string;             // 发送时间
  status: 'sent' | 'failed';    // 发送状态
  recipients: string;           // 收件人
}
```

### 3.2 问题类型

系统支持以下问题类型：
- `inventory`: 库存异常
- `order`: 订单异常
- `logistics`: 物流异常
- `system`: 系统错误
- `other`: 其他问题

### 3.3 状态定义

解决状态：
- `unsolved`: 未解决
- `solved`: 已解决

邮件状态：
- `sent`: 已发送
- `unsent`: 未发送
- `failed`: 发送失败

## 4. 功能流程

### 4.1 筛选异常记录

用户可通过以下条件筛选异常记录：
1. 时间范围：选择开始和结束日期
2. 问题类型：库存异常、订单异常、物流异常、系统错误、其他问题
3. 解决状态：未解决、已解决
4. 邮件状态：已发送、未发送、发送失败
5. 渠道：Amazon、Shopify、Walmart、eBay、其他
6. 关键词：支持对订单ID、系统ID和描述进行关键词搜索

### 4.2 查看异常详情

1. 用户点击查看详情图标
2. 系统打开详情对话框，显示异常的完整信息
3. 详情包括：创建时间、更新时间、渠道、订单ID、问题类型、描述、状态、邮件状态等
4. 如果有邮件发送历史，则显示历史记录
5. 如果异常已解决，显示解决时间和解决方案

### 4.3 发送邮件通知

1. 用户可以通过两种方式打开发送邮件对话框：
   - 点击表格中记录的"发送邮件"图标
   - 在查看详情对话框中点击"发送邮件"或"重新发送"按钮
2. 系统加载相关记录的信息，预填邮件表单：
   - 若是首次发送（未发送状态），使用默认邮件模板
   - 若是重新发送（已发送状态），系统会尝试使用之前的邮件内容作为模板
3. 用户可以：
   - 添加、选择或删除收件人（支持多选）
   - 添加、选择或删除抄送人（支持多选）
   - 编辑邮件主题和内容
   - 系统提供常用联系人列表，方便快速选择
4. 用户点击确认发送
5. 系统发送邮件
6. 系统更新邮件发送状态和最后发送时间
7. 系统刷新数据列表

#### 4.3.1 收件人管理

邮件通知模块支持灵活的收件人管理：

1. **多选功能**：
   - 用户可以为一个邮件添加多个收件人
   - 支持直接输入新的邮箱地址
   - 支持从预设的常用联系人列表中选择

2. **可删除功能**：
   - 用户可以方便地删除已添加的收件人
   - 移除收件人时不影响其他已选择的收件人

3. **快速输入**：
   - 支持按Enter键快速添加新的邮箱地址
   - 支持输入部分内容进行筛选和搜索

4. **常用联系人**：
   - 系统预设了常用部门联系人列表
   - 包括仓库管理员、订单客服、物流部门、IT支持和客户支持等

### 4.4 批量发送未解决异常邮件

1. 用户可通过以下两种方式选择要发送邮件的异常记录：
   - 在表格中勾选一个或多个异常记录
   - 不选择任何记录（此时将处理所有未解决且未发送邮件的异常）
2. 用户点击页面顶部的批量发送按钮
3. 系统弹出批量发送对话框，显示以下信息：
   - 选择记录的数量统计
   - 符合条件的记录数量（未解决且未发送状态）
   - 按问题类型的统计明细
4. 用户可以选择配置统一收件人和抄送人：
   - 若指定统一收件人，则所有邮件发送给同一收件人
   - 若不指定，则系统根据问题类型自动选择相应的默认收件人
5. 用户确认发送
6. 系统依次发送所有邮件，跟踪成功和失败数量
7. 系统完成后显示发送结果统计
8. 系统自动刷新数据列表

### 4.5 标记异常为已解决

1. 用户在详情对话框中选择标记为已解决
2. 系统打开解决方案输入对话框
3. 用户输入解决方案或处理结果
4. 系统更新异常状态为"已解决"
5. 系统记录解决时间和解决方案

## 5. 业务规则

### 5.1 异常状态规则

1. 新创建的异常记录默认为"未解决"状态
2. 异常一旦标记为"已解决"，状态不能回退为"未解决"
3. 只有"未解决"的异常可以标记为"已解决"

### 5.2 邮件通知规则

1. 只有邮件状态为"未发送"的记录可以发送邮件
2. 邮件发送后，状态自动更新为"已发送"
3. 如果邮件发送失败，状态更新为"发送失败"
4. 每次发送邮件的记录都会保存在邮件历史中
5. 发送邮件时，系统会自动更新"更新时间"字段
6. 批量发送邮件时，系统会自动为每种问题类型选择相应的默认收件人

### 5.3 数据显示规则

1. 表格默认按照创建时间倒序排列（最新的记录在前）
2. "更新时间"字段显示最后发送邮件的时间或创建时间（如果未发送过邮件）
3. 如果系统订单ID存在，则显示为可点击链接，点击后导航至订单详情页
4. 问题描述如果过长，在表格中会截断显示，完整内容在详情对话框中查看

### 5.4 权限规则

1. 查看异常日志需要具有"异常管理"或"系统管理"权限
2. 发送邮件通知需要"通知管理"权限
3. 标记异常为已解决需要"异常处理"权限

## 6. 集成点

### 6.1 与订单系统集成

1. 系统订单ID链接到订单详情页
2. 订单相关异常可以从订单系统自动生成

### 6.2 与库存系统集成

1. 库存异常可以从库存系统自动生成
2. 库存同步过程中的错误会记录为系统异常

### 6.3 与邮件服务集成

1. 异常日志模块通过邮件服务发送通知
2. 邮件模板可以在邮件配置模块中设置

## 7. 异常处理流程建议

1. 定期检查未解决的异常
2. 优先处理高优先级的异常（如影响客户订单的异常）
3. 解决异常后及时更新状态和解决方案
4. 对反复出现的异常进行根本原因分析
5. 建立异常处理的最佳实践和标准操作流程

## 8. 性能考虑

1. 异常日志数据可能会随时间增长变大
2. 建议实施数据归档策略，例如将3个月以上的已解决异常归档
3. 使用分页加载和按需加载详情来提高页面性能
4. 对搜索条件进行索引优化，特别是时间范围和关键词搜索

## 9. 扩展建议

4. 异常预警机制和主动监控
